## 2. Разделение типов данных (Data Provenance)

Система категоризирует каждую величину по одному из пяти статусов:

1. **Факт (Observed Transactions & Offers)**:
   - Фактические завершенные сделки производителей, твердые заявки покупателей (bids), прайс-листы продавцов (asks) и биржевые/отраслевые индексы.
   - Обязательно содержат дату наблюдения (`observation_date`), дату публикации (`published_date`), источник (`source`), ссылку на лот/документ (`source_ref`) и подтвержденный базис.
2. **Макро-факт (Live/Cached Macro)**:
   - Официальные курсы валют (USD/RUB, KZT/RUB) и ключевая ставка Банка России.
   - Загружаются напрямую через XML API ЦБ РФ (`cbr.ru`), кэшируются локально. При недоступности сети отображаются как «кэшированные» с точной датой фиксации, без фиктивных значений.
3. **Пользовательские допущения (Assumptions)**:
   - Смета расходов на доставку в Москву (фрахт фуры, упаковка, погрузка, норма потерь в пути, маржа оптовика).
   - Нормативы хранения (усушка, отход по гнили, затраты на охлаждение, ставка дисконтирования).
   - Сценарные шоки (импорт, курс).
4. **Демо-режим (Demo / Illustrative Data)**:
   - Исторический 26-недельный профиль зафиксирован датой **24 октября 2026 года** (`issue_date = 2026-10-24`).
   - Используется **исключительно для демонстрации интерфейса** и снабжен сквозным бейджем `ДЕМО (иллюстративные данные)`.
   - Никогда не сдвигается вперед просто от изменения сегодняшней календарной даты.
5. **Недостаточно данных (Insufficient Data)**:
   - Если количество валидных наблюдений недостаточно для построения статистически значимого прогноза или валидации, система прямо выводит статус `insufficient_data` и базовую оценку «без изменений» (naive), блокируя показ неподтвержденных интервалов и маркетинговых обещаний.

## 3. Мост издержек «Волгоград → Москва» (Cost Bridge)

Вместо устаревшего фиксированного коэффициента $2.08$, связь между ценой склада в Волгограде и оптовой ценой в Москве рассчитывается через физическую смету затрат и налог:

$$\text{DeliveryCost}_{\text{net}} = \frac{\text{Freight}}{\text{TruckCapacity}} + \text{Packaging} + \text{Handling}$$

$$\text{CostWithLoss} = \frac{P_{\text{wh, ex-VAT}} + \text{DeliveryCost}_{\text{net}}}{1 - \text{TransitLoss}} - P_{\text{wh, ex-VAT}}$$

$$P_{\text{msk, ex-VAT}} = P_{\text{wh, ex-VAT}} + \text{CostWithLoss} + \text{Margin}$$

$$P_{\text{msk, incl-VAT}} = P_{\text{msk, ex-VAT}} \times (1 + \text{VAT})$$

### Базовые параметры моста (редактируемые в интерфейсе):
- Фрахт фуры 20 т (Волгоград — Москва): **135 000 ₽** ($6.75$ ₽/кг).
- Фасовка в сетку: **1.50 ₽/кг**.
- Погрузка и складская обработка: **1.00 ₽/кг**.
- Технологические потери в пути (усушка, бой): **1.5%**.
- Маржа трейдера/оптовика: **1.50 ₽/кг**.
- Ставка НДС: **10%** ($0.10$).

При наличии одновременных парных наблюдений цен в Волгограде и Москве в одну и ту же неделю система рассчитывает фактический рыночный спрэд, сравнивает его с расчетным мостом и выводит расхождение.

## 4. Экономика хранения: «Продать сейчас vs Хранить до весны»

Решение о закладке лука на хранение принимается на основе сравнения **чистой выручки сегодня** с **ожидаемой чистой выручкой позже на 1 кг изначально заложенного объема**, с учетом мультипликативных потерь и альтернативной стоимости денег.

### 4.1. Мультипликативный выход товарного лука:
$$\text{SaleableYield} = (1 - \text{Shrink}) \times (1 - \text{Rot})$$
*(Потери на усушку и отход по гнили не складываются арифметически, а перемножаются).*

### 4.2. Эффективная цена реализации с учетом снижения сорта:
$$P_{\text{eff}} = P_{\text{future}} \times \left(1 - \text{DowngradeShare} \times \text{DiscountRate}\right)$$

### 4.3. Прямые и финансовые издержки хранения:
$$\text{DirectCosts} = \text{Handling}_{\text{in/out}} + (\text{Energy} \times M) + (\text{Sorting} \times \text{SaleableYield})$$

$$\text{FinancingCost} = P_{\text{now}} \times \left(\frac{r_{\text{annual}}}{12} \times M\right)$$

$$\text{TotalStorageCost} = \text{DirectCosts} + \text{FinancingCost}$$

### 4.4. Чистая выручка и экономический эффект:
$$\text{NetNow} = P_{\text{now}} - \text{SellNowCosts}$$

$$\text{NetLater} = (P_{\text{eff}} \times \text{SaleableYield}) - \text{TotalStorageCost}$$

$$\text{GainPerKgStored} = \text{NetLater} - \text{NetNow}$$

### 4.5. Безубыточная будущая цена:
$$P_{\text{break-even}} = \frac{\text{NetNow} + \text{Handling}_{\text{in/out}} + (\text{Energy} \times M)}{\text{SaleableYield} \times \left(1 - \text{DowngradeShare} \times \text{DiscountRate} - \frac{\text{Sorting}}{P_{\text{eff}}}\right)}$$

Полевая себестоимость выращенного урожая трактуется строго как **невозвратные издержки (sunk cost)** и не участвует в маржинальном сравнении отгрузки сегодня против хранения.

## 5. Баланс спроса и предложения

Уравнение баланса рынка исключает ошибки в знаках запасов и защищено от деления на ноль:

$$\text{AvailableSupply} = (P_{\text{harvest}} \times w_{\text{weather}}) + (I_{\text{import}} \times r_{\text{restrictions}}) + S_{\text{opening}}$$

$$\text{DeficitIndex} = \frac{D_{\text{consumption}}}{\text{AvailableSupply}}$$

- Переходящие запасы прошлого сезона ($S$) **увеличивают** доступное предложение (знак «плюс» в знаменателе).
- При базовых региональных параметрах ($D = 2.20$ млн т, $P = 1.65$ млн т, $I = 0.35$ млн т, $S = 0.25$ млн т) предложение составляет $2.25$ млн т, а индекс дефицита равен $0.98$ (сбалансированный рынок), устраняя противоречие старой версии (где фигурировал жестко заданный индекс $1.21$).

## 6. Валидация и бэктестинг прогнозов

### 6.1. Предотвращение утечки данных (Leakage Prevention)
Для каждого шага бэктеста $t$:
- Модель обучается **исключительно** на наблюдениях, у которых доступная дата $\le t$ (`availableDate <= origin`).
- Запрещено использовать будущую информацию о средних ценах сезона, сезонных коэффициентах или макропоказателях.

### 6.2. Скользящее окно (Rolling-Origin Backtest)
- Разбиение: очищенный период настройки (purged tuning) и отложенная выборка (holdout split, 40% последних наблюдений).
- Оцениваемые горизонты: **W+1, W+4, W+8, W+13, W+26**.
- Метрики:
  - **MAE (Mean Absolute Error)** в ₽/кг;
  - **Bias (смещение)** в ₽/кг;
  - **Коэффициент мастерства относительно наивного прогноза** ($\text{Skill} = 1 - \frac{\text{MAE}_{\text{model}}}{\text{MAE}_{\text{naive}}}$);
  - Число ретроспективных точек $n$ и даты периода тестирования.
- Калиброванные интервалы: 80% и 95% рассчитываются по эмпирическим квантилям абсолютных ошибок валидационной выборки (Conformal Prediction) с измерением фактического покрытия (Coverage %).

## 7. Безопасность и архитектура AI-консультанта

1. **Защита от инъекций промпта (Prompt Injection)**:
   - Контекст рынка формируется на сервере в виде строго валидированного JSON-среза (`buildSnapshot`).
   - Все текстовые поля экранируются, глубина объектов ограничена 7 уровнями, общий размер ограничен 32 КБ.
   - Пользовательский ввод очищается и ограничивается 1000 символами.
2. **Безопасный рендеринг (Safe Markdown)**:
   - Полностью удален вызов `dangerouslySetInnerHTML`.
   - Ответ AI разбирается встроенным детерминированным парсером `shared/safeMarkdown.js`, который создает безопасное дерево React-элементов без исполнения произвольного HTML или скриптов.
3. **Хранение секретов**:
   - Ключи API (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) хранятся строго на сервере и никогда не передаются в браузер.
   - При отсутствии ключа платформа возвращает честный HTTP 401 с понятной инструкцией, не имитируя работу нейросети.

## 9. Внешние подключения и необходимые доступы

1. **ЦБ РФ (Курсы валют и ключевая ставка)**:
   - Подключен реальный XML API Банка России (`cbr.ru/scripts/XML_daily.asp`). Не требует ключей или подписки.
2. **Агросервер / ПроЗерно / Отраслевые площадки**:
   - Прямой платный API отсутствует. Реализован интерфейс валидации и импорта выгрузок в формате CSV.
3. **Росстат / Минсельхоз РФ (Сбор урожая и запасы)**:
   - Загружаются через CSV индикаторов по мере публикации официальных бюллетеней.
4. **ФТС РФ (Импорт)**:
   - С 2022 года детальная статистика внешней торговли агрегируется; сценарии по импорту из Казахстана управляются в виде сценарных шоков с явной маркировкой допущений.
5. **AI-ассистент**:
   - Требуется бесплатный ключ Gemini API (`GEMINI_API_KEY`) в файле `.env.local`.
